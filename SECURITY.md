# Security

ferroplan is a planning engine: it parses untrusted PDDL/HDDL text and returns
plans, policies, and structured JSON. Treat untrusted domain/problem files the
way you treat untrusted build inputs — malformed or hostile input should
produce a typed, stage-named error, never a panic, and embedders (WASM, MCP,
the Python binding, `Session` hosts) should assume the parser is a parser, not
a sandbox.

## Reporting

Report vulnerabilities privately through [GitHub's security-reporting
surface](https://github.com/seanchatmangpt/ferroplan/security/advisories/new)
rather than publishing exploit details in a public issue. Include the exact
domain/problem files and the commit SHA you tested against, plus the command
and its output — a report with a reproducible subject is actionable; a
description alone is not.

## Embedded and hostile-input boundaries

- **Parser is not a sandbox.** The PDDL/HDDL front-ends accept untrusted text;
  they do not execute it. But a parse of hostile input runs *in your process*
  — resource limits (`FF_TIME_LIMIT`, `FF_MEM_BUDGET_GB`,
  `Options::wall_ms`) are the containment surface, and callers embedding the
  planner should set them.
- **WASM demo** plans client-side in the browser. Its containment is the WASM
  sandbox plus the budget knobs the demo sets; the server never sees your
  domain text.
- **MCP server** exposes `solve`/`validate`/`decompose` over stdio. It inherits
  the caller's process authority — do not point it at files you would not read
  yourself.

## Typed refusals and the receipt culture

The engine's contract is fail-loud: unsupported shapes (`:durative-action` in
HDDL, timed PDDL3 constraint operators, unbounded oneof positions) are refused
by name with typed, stage-named errors — honest refusal, never silent
truncation. Security reports are held to the same bar:

- name the exact subject (commit SHA),
- name the command and exit,
- distinguish what was *observed* from what is *inferred*,
- do not claim a boundary is safe from queued metadata or a historical success
  at another SHA.

If a fix requires external action that is unavailable, the status is recorded
as `BLOCKED:<reason>` rather than mocked into passing.

## Benchmarks and claims

Benchmark numbers are claims with witnesses: every published figure traces to
a scoreboard or RESULTS file regenerated by `benchmarks/standings.py`. A
security-relevant claim ("panic-free on malformed input", "budget-honest")
must be backed by the test or corpus that witnesses it, same as any other
claim.

# Village stress suite — where the monolithic plan breaks down

`rpg-world`, built out to full scale: "raise a village," generated by
`../gen_village.py M_AGENTS HOUSES PRESTOCK SPREAD EXTRAS`. Each scenario demands
the *whole* outcome — square, houses, well, walls, feast — in one plan, one shot,
a crew of craftsmen thrown at it at once, hunting the cliff edge.

## Results (M4, contended; 90s cap)

| scenario | what | result |
|---|---|---|
| `t0-build-floor` | 1 agent, **processed** materials seeded, build square (2 houses) | **makespan 11** ✅ |
| `t1-square-pre-hub` | 2 agents, raw seeded, 2 houses+square, no travel | NO PLAN (7s) |
| `t2-square-raw-hub` | 3 agents, gather from scratch, 2 houses+square | NO PLAN (14s) |
| `t3-pre-spread` | 3 agents, raw seeded, +well+feast, travel | NO PLAN (9s) |
| `t4-raw-hub-big` | 4 agents, 3 houses+square+well, from raw | NO PLAN (20s) |
| `t5-fullday-spread` | 6 agents, 3 houses+square+well+walls+feast, travel | NO PLAN (18s) |
| `t6-everyone` | 8 agents, 4 houses + everything + coin, travel | NO PLAN (24s) |

## What the numbers say (the honest envelope)

1. **The build step alone holds fine** (`t0`, 11): the temporal search eats
   ~10–15-action plans without flinching.
2. **Processing plus building, in one plan, breaks it.** A village goal hides a
   long chain underneath — saw planks, mason blocks, fire bricks, then raise each
   structure — 20+ sequential actions deep, past what the decision-epoch search
   can reach. Same `#45` temporal-search-depth ceiling, now wearing a realistic shape.
3. **More craftsmen make it WORSE, not better.** Same goal, 1 / 2 / 4 agents:
   11s → 17s → 25s, NO PLAN across the board. The monolithic search finds no
   parallelism to exploit — every extra agent just widens the branching it has to wade through.

## The takeaway — architecture, not a bug

Nobody plans a whole village in one shot. The scheduler carves it into
**contract-sized sub-tasks** — "saw 12 planks," "mason 12 blocks," "raise house s0" —
each a short plan a lone craftsman solves fast (see `examples/rpg-world/
contracts/`), then hands them out across the workforce. The shared stockpile
carries state between contracts. This is load-bearing: it's the only route to a
finished village, and it's also where the parallelism actually lives (N contracts
on N craftsmen) — the planner itself won't parallelize a monolithic goal.

Engine levers that raise the per-contract ceiling: a location/numeric-aware
temporal heuristic plus helpful-action pruning (`#45`), and the faster derived-closure
(`#75`) for bigger maps.

# Hard — adversarial problems: where the engine breaks

12 problems built to *break* the temporal search — each solvable-in-principle,
so a failure is read as a real search limit, not a dead goal. Generated by
`../../../benchmarks/scale/gen_hard.py`.

**As of v0.3.0, all 12 clear under default options.** Ten go down directly (all
sub-100 ms) — demand-guidance tiers, numeric-threshold landmarks, the
default-on goal-relevance pruning doing the work. The two big conjunctive
orders (`order-8`, `order-12`) fall to the **on-failure escalation ladder**,
which hands them to the decomposer the moment the monolithic search exhausts
(~110–120 s each — hardware/thread-count dependent — plans validated).
`ff --decompose` still takes them directly, in a fraction of a second, and
lays out the contract breakdown.

| `log-scarcity` | ✅ makespan 7, 8 ms | tight allocation: split exactly 4 logs between planks + charcoal |
| `tech-steel` | ✅ makespan 39, 10 ms | deep DAG: ore+coal→ingot→steel ×2 |
| `tech-bronze` | ✅ makespan 68, 15 ms | deep DAG: copper+tin→ingots→bronze ×2 |
| `tech-bronze-steel` | ✅ makespan 67, 45 ms | two deep DAGs at once |
| `bread-line` | ✅ makespan 15, 31 ms | deep DAG: farm→grind→bake (see note) |
| `mint-fortune` | ✅ makespan 70, 37 ms | coin 15 via three interchangeable paths (sell/mint/haul) |
| `farmstead-big` | ✅ makespan 31, 8 ms | cyclic: 5 crop cycles on one field |
| `gather-build` | ✅ makespan 18, 8 ms | the village shape (small): travel→mine→mason→build |
| `order-8` | ✅ makespan 30 (ladder→decomposer, ~112 s) | 8-part conjunctive order |
| `order-12` | ✅ makespan 60 (ladder→decomposer, ~117 s) | 12-part conjunctive order |

> **bread-line note.** Until v0.3.0 this instance was *unsolvable by
> construction* — a domain bug: `bake-bread` produced `meals` directly, leaving
> the `bread` fluent with no producer, breaking the hard-set's
> solvable-in-principle contract. Fixed: the domain now bakes bread from flour.
> The instance is the real deep DAG its name promised, and it clears. Its
> distilled failing shape (`flour ≥ 2` on a fully-featured hub) is what pushed
> **goal-relevance pruning** into the default tier — dozens of goal-irrelevant
> unbounded accumulators (forage-food, gather-herbs, …) were drowning the
> complete search. Pruned to the goal-relevant op subspace, a ~45 s exhaustion
> became a ~30 ms solve.

## How each original failure shape was retired

1. **Deep dependency DAGs** (`tech-*`) — the numeric-threshold **landmark term** +
   the **`Numeric` demand tier** (default since v0.2) restore the gradient
   delete-relaxation loses when contributions converge.
2. **Multi-path numeric goals** (`mint-fortune`) — same demand tier: cumulative
   availability holds steady, no dithering between interchangeable producers.
3. **Cyclic resource regeneration** (`farmstead-big`, `bread-line`) — demand
   survives consumption across rounds; pruning keeps the search out of the
   irrelevant-accumulator swamp.
4. **The village shape** (`gather-build`) — **goal-relevance pruning**, default-on
   since v0.3.0 (previously behind `FF_TDEMAND`).
5. **Big conjunctive goals** (`order-8/12`) — the architecture's answer is the
   **decomposer**: split the order into per-part contracts, stitch a validated
   plan. `order-5` clears whole; 8+ wants splitting. Since the escalation ladder,
   the handoff runs itself — a failed monolithic search falls through to the
   decomposer, no flag needed.

## What's robust

- **Deep travel is fine.** A 20-hop corridor solves — `travel` gives the heuristic a
  clean distance gradient, so depth alone isn't the enemy.
- **Tight allocation is fine.** `log-scarcity` splits 4 logs correctly (saw 2 +
  burn 2) instead of greedily burning them all on one product.
- (From the broader suite: deep *linear* accumulation solves too — `deepmine` runs
  15 mining ops.)

The **exact thresholds** for each shape (binary-searched), plus the decomposition
ruleset for the subproblem-maker, are logged in
[`../../BORDERS.md`](../../BORDERS.md) — linear accumulation holds to ~2000 ops,
travel to ~100 hops.
